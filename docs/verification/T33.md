# T33 — Browser journeys and visual quality (evidence)

Recorded 31 October 2026. Everything below ran against the **real local stack**, not mocks: Angular dev server (`ng serve`, :4200, proxying `/api` and `/r/`), the Docker API and analytics worker, PostgreSQL, Redis and Mailpit. Browser: Chromium (Playwright, headless), fresh browser contexts per journey, so no state leaked between runs.

The scripts are in [`scripts/`](scripts/). Each is a function taking a Playwright `page` and returning its checks; they were run through the Playwright MCP tool. Journeys that need an admin read placeholders (`__ADMIN_EMAIL__`, `__ADMIN_PASSWORD__`) that are filled in an uncommitted copy; no credentials are committed.

## 2. Visual and accessibility matrix: 120 of 120 states clean (after fixes)

Fifteen screens: home, log in, sign up, check email, forgot password, reset (invalid link), verify (invalid link), report, app 404, short-link 404 page (API), your links, link editor, analytics, account, administration.

- **90 states**: every screen in light and dark at 320, 768 and 1280 px.
- **15 states**: an emulated touch phone (390 px, coarse pointer, `isMobile`).
- **15 states**: reduced motion (`prefers-reduced-motion: reduce`).

Checked in every state: horizontal overflow; text contrast against its real background (4.5:1, 3:1 for large text); text clipped without an ellipsis or deliberate clamp; controls without a name; fields without a label; duplicate ids; heading order (first heading h1, no skipped levels); exactly one `main`; images without `alt`; targets under 24 × 24 px (WCAG 2.5.8; inline links in a sentence exempt). Touch pass: every control at least 44 px tall. Reduced-motion pass: nothing transitions or animates.

First run: 4 problems, all fixed, then a full re-run was clean.

| Problem found | Fix |
|---|---|
| Sign-up overflowed 9 px at 320 px: Google's button iframe is ~35 px wider than the width requested (transparent padding) | The Google slot centres the button and clips only that padding |
| "Forgot password?" and the home sign-up invitation were 21 px tall on desktop (below 24 px) | Standalone auth links are at least 24 px tall everywhere, 44 px on touch screens |
| The short-link failure page's logo link was 30 px tall on touch | 44 px tap height |
| Admin status tabs were 34 px tall on touch | 44 px on coarse pointers |

**Visual review.** Contact sheets of the 90 screenshots were reviewed by eye (public, auth, workspace and admin; both appearances). No broken layout, clipping or overlap. Observations, not changed: in dark mode the petrol primary buttons have low emphasis against the dark surface (their text contrast passes); the admin status tabs wrap onto two rows at 320 px.

## 3. Findings recorded during the journeys

- **By design, recorded for the product owner:** every guest attempt counts toward the hourly quota (5) and the suspicious-activity threshold (2 per 10 minutes), valid or not. A challenged attempt and its verified retry are two attempts, so once a guest is challenged each link costs two of the five hourly attempts (in practice about two to three links per hour). This matches the design ("quota is counted before validation"; recent failures are a challenge trigger) but may be stricter than intended for real users. Open question: should a request rejected only for `CHALLENGE_REQUIRED` count toward the quota?
- **By design:** the per-network email limit (10 per hour across sign-up, resend and forgot-password) stopped repeated test sign-ups, with the message "Too many attempts. Please try again in about 58 minutes." Local counters were cleared between runs.
- **By design:** the server checks the challenge before the URL, so an invalid URL from a suspicious network is first asked for verification.

## 5. Reproducing

1. Start the stack (`docker compose up -d`) and the web app (`npm start -w @shortlist/web`).
2. Grant a local test account the admin role: `docker compose exec api node src/cli/set-role.js <email> admin`.
3. Clear local rate-limit counters if earlier runs used them (development only): `docker compose exec redis redis-cli --scan --pattern 'rate:*' | xargs -r docker compose exec -T redis redis-cli DEL`.
4. Run each script with a Playwright runner that passes a `page` (the MCP `browser_run_code_unsafe` tool was used here), filling the admin placeholders in an uncommitted copy.
